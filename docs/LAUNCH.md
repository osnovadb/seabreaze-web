# Запуск Portal v2 на бою (hscp-01)

Сейчас бой GetsEstate на hscp-01 (`/opt/getsestate`, служба `getsestate-portal`, таймер `getsestate-portal-tick`). Там работает v1.
Стенд v2 — ams (`/opt/ge-portal2`, ge-portal2.pdna.pro). Переключение на v2 — только по решению Дениса.

## 1. Что нужно от Дениса

| Что | Зачем | Куда |
|---|---|---|
| SMTP: адрес сервера, логин, пароль; адрес отправителя | приглашения, сброс пароля, уведомления | `SMTP_URL=smtp://user:pass@host:587`, `SMTP_FROM="GetsEstate <no-reply@…>"` |
| Бот Telegram: токен и имя (через @BotFather) | уведомления команде и партнёрам | `TG_BOT_TOKEN`, `TG_BOT_NAME` |
| Ключ API Profitbase Sea Breeze (pb21387) с правом чтения и записи статусов; IP боя в белом списке | каталог, цены, статусы, планы этажей, бронь у застройщика | `PB_KEY_SEABREEZE`, затем «Источники → Подключить Profitbase» |
| Статусы у Sea Breeze: «Бронь GetsEstate» (база BOOKED), «Продано через GetsEstate» | запись брони и продажи | alias — в настройках источника |
| Домены portal.getsestate.com и т. д. в Cloudflare | вход партнёров | `PUBLIC_URL=https://portal.getsestate.com` |
| Юрлицо, адрес, e-mail для запросов по данным; вычитка иврита | политика конфиденциальности и согласие (`lib/legal.ts`) | поля в квадратных скобках |
| Планы оплаты Premium Residence | калькулятор и график платежей в карточке, брони и подборке | «Объекты → Premium → Планы оплаты» |

## 2. Схема каталога (суперпользователь базы, один раз)

`db/catalog-v2.sql`: тип «кладовка», триггер журнала квартиры, права портала на sources, sync_runs, status_map и type_map.

```
psql -U <superuser> -d seabreeze -f db/catalog-v2.sql
```

## 3. Миграции портала

`npm run db:migrate` с `DATABASE_URL` боя. Нужны миграции 011–033.

## 4. Окружение боя (portal.env)

- **Добавить:** `PUBLIC_URL`, `SMTP_URL`, `SMTP_FROM`, `TG_BOT_TOKEN`, `TG_BOT_NAME`, `PB_KEY_SEABREEZE`.
- **Не задавать:** `STAND_LABEL` (подпись «Тестовый стенд»), `ALLOW_IMPERSONATE_WRITE`, `PB_KEY_MOCK`.
- **Проверить:** `LEADS_SECRET` и `LEADS_ORIGINS`. Секрет на бою должен быть свой, не стендовый.

## 5. Службы

- **tick:** таймер раз в 15 минут — как сейчас.
- **Падение tick:** добавить `OnFailure=getsestate-portal-tick-failed.service`, unit по образцу `ge-portal2-tick-failed` (запускает `scripts/tick-failed.mjs`).
- **Заглушка Profitbase:** служба `ge-pbmock` есть только на стенде, на бой не ставить.
- **Origin только через Cloudflare:** порты 80/443 боя открыть лишь для диапазонов Cloudflare (ufw, список с cloudflare.com/ips). Иначе `cf-connecting-ip` можно подделать прямым запросом, и лимит входа «20 попыток с IP» обходится. Лимит по e-mail работает в любом случае.

## 7. Резервные копии

- **На hscp-01:** `getsestate-backup.timer` — дамп базы и uploads, 14 дней.
- **Копии вне сервера нет.** Нужно ежедневно копировать `backups/` на второй сервер (ams), например rsync по ключу в 03:30.
- **Восстановление:** проверять раз в месяц на стенде.

## 8. Проверка после переключения

- **Вход:** владелец входит; приглашение нового партнёра приходит письмом, пароль задаётся по ссылке.
- **Profitbase:** «Источники → Запустить сейчас» — проверено N, ошибок нет. Цена, изменённая в Profitbase, видна через 15 минут.
- **Бронь:** подтверждение брони офисом — в Profitbase квартира в статусе «Бронь GetsEstate».
- **Заявки с сайтов:** тестовая заявка с сайта рынка видна в «Заявках с сайтов».
- **Ошибки:** искусственная ошибка доходит до владельца уведомлением.
- **Индексация:** закрыта (`X-Robots-Tag: noindex`), пока не решено иначе.
