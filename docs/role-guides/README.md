## Экраны с номерами на кнопках

К каждой роли — альбомные листы «<язык> · <роль> · экран N»: снимок портала, оранжевые рамки и номера на кнопках, справа расшифровка (у иврита зеркально).

Переснять, когда поменялся интерфейс:
1. Туннель к QA-экземпляру: `ssh -f -N -L 3043:127.0.0.1:3043 root@72.56.89.30`.
2. `cd docs/role-guides/shots && npm i puppeteer-core@23.11.1 && node shoot.mjs ru` (en, de, he) — снимки и координаты кнопок в `out/<язык>/`. Только просмотр страниц, данные не меняются; строки автотестов «QA …» и строки с чужой почтой прячутся, телефоны маскируются.
3. `node preview.mjs ru prev.png <id…>` — проверить, что рамки попали в кнопки.
4. В Figma пересобрать листы и залить картинки через upload_assets (заготовки `img:<язык>:<id>`).

Кадры и подписи к номерам — `shots/plan.json` (кнопка ищется по русской подписи через словарь портала или по CSS-селектору).

## Сценарии пошагово

Раздел «Сценарии · пошагово» под сеткой ролей (y ≥ 9700, колонки языков x = col·4600): 6 сценариев — завести клиента, подобрать квартиры и отправить подборку, варианты оплаты в калькуляторе, показ клиенту, холд и запрос брони, подтверждение брони офисом. Каждый шаг — альбомный A4: что сделать, снимок с номерами, расшифровка.

`shots/scen.json` — шаги (страница, подготовка формы `prep`, цели `t`, действие `do`), `shots/scen.mjs` — исполнитель: каждый шаг снимается на 4 языках, действие выполняется один раз на QA-экземпляре. Сценарии меняют данные QA-базы (клиент, вариант, холд, бронь) — перед повтором заведите нового демо-клиента и свободную квартиру в `vars`.
Грабли: кнопки серверных форм нажимать по тексту, а не `form button` (попадёт в «Выйти»); числовые поля заполнять через native setter + событие input; режим показа берёт язык в момент входа — запускать его под каждый язык.
